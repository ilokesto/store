# 쓰기 가능한 focus와 store family

두 API 모두 `@ilokesto/store` 루트에서 제공하는 프레임워크 중립 export입니다.

## 부모 값에 초점 맞추기

`focus(parent, read, write, options?)`는 `WritableFocus<Selection>`을 반환합니다.
getter는 얕은 읽기 전용 부모 스냅샷을 받습니다. write-back 함수는 현재 부모 상태와
다음 부분 값을 받아 새 불변 부모 상태를 반환해야 합니다. 인자를 직접 변경하면 안 됩니다.

```ts
import { createStore, focus } from '@ilokesto/store';

const account = createStore({ user: { name: 'Ada', age: 30 }, theme: 'dark' });
const name = focus(
  account,
  state => state.user.name,
  (state, name) => ({ ...state, user: { ...state.user, name } }),
);
name.set('Grace');
name.update(previous => previous.toUpperCase());
name.setState(previous => previous + '!');
name.dispose();
```

`set(value)`는 함수도 리터럴로 저장합니다. `setState(action)`은 교체 값 또는 updater를
받고, `update(updater)`는 부분 값을 명시적으로 변환합니다. 모든 쓰기는 부모의
`update`를 호출하므로 부모 middleware가 지연, 변환, 거부할 수 있습니다.
getter, 부분 값 updater, write-back은 요청 시점의 스냅샷이 아니라 middleware가
action을 전달하는 시점의 부모 상태에서 실행됩니다. 부분 값이 `Object.is`로 같으면
write-back을 호출하지 않고 기존 부모를 반환합니다. 이때도 action은 부모 middleware를
통과합니다. 중첩 writable focus도 루트 middleware 경로를 보존합니다.

문자열 경로 해석이나 암묵적 객체 생성은 없습니다. 누락된 값은 getter와 setter에서
명시적으로 처리합니다.

```ts
const profile = createStore<{ name?: string }>({});
const optionalName = focus(
  profile,
  state => state.name,
  (_state, name) => name === undefined ? {} : { name },
);
optionalName.set('Ada');
optionalName.set(undefined);
optionalName.dispose();
```

### 읽기 전용 뷰, 동등성, 소유권

`focus(parent, read, options?)`는 쓰기 메서드가 없는
`DisposableReadableStore<Selection>`을 반환합니다. 부모가 쓰기 가능해도 같습니다.
write-back overload는 `update`가 있는 부모가 필요하며 읽기 전용 부모에서 쓰기 권한을
만들지 않습니다. 쓰기 가능한 결과도 자체 middleware 등록 메서드는 제공하지 않습니다.
middleware는 부모에 등록합니다.

읽기와 구독은 `derived`에 위임합니다. `options`는 `DerivedOptions<Selection>`으로,
`equalityFn` 기본값은 `Object.is`, `cacheSize` 기본값은 `1`입니다. 출력 동등성은
기존 출력 참조를 유지하고 같은 값의 알림을 생략하지만 쓰기 시점의 `Object.is`를
대체하지 않습니다. 읽기는 지연 계산하며 최신 값을 반환하고, `getInitialState`는
부모 초기 상태를 선택합니다. 소스 연결은 뷰 구독자가 있는 동안만 유지됩니다.
구독은 derived의 배치 처리, 안정화된 재진입 전달, 중복 리스너의 독립 소유권,
selector의 다음/이전 값 기준선을 그대로 따릅니다.

getter, setter, 동등성 함수는 순수하게 작성합니다. 스냅샷은 얕은 읽기 전용 타입이며
복제되거나 런타임에서 동결되지 않습니다. `dispose()`는 멱등적이고 영구적이며
구독과 대기 중 알림을 해제하지만 부모는 해제하지 않습니다. 이후 읽기, 구독, 쓰기는
오류를 던집니다. 해제 후 전달된 지연 middleware action도 부모를 변경하기 전에
오류를 던집니다. 기존 unsubscribe 함수는 안전하게 호출할 수 있습니다.

## 키별 스토어를 명시적으로 소유하기

`createStoreFamily(create, options?)`는 `StoreFamily<Key, Instance>`를 반환합니다.
factory는 구조적 readable 스토어를 만들며 쓰기 메서드를 포함한 정확한 인스턴스 타입을
보존합니다.

```ts
import { createStore, createStoreFamily } from '@ilokesto/store';

const counters = createStoreFamily(
  (id: string) => createStore({ id, count: 0 }),
  {
    onCreate: (instance, key) => console.log('created', key),
    onRemove: (instance, key) => console.log('removed', key),
  },
);
const first = counters.get('one');
first.update(state => ({ ...state, count: state.count + 1 }));
counters.get('one') === first; // true
counters.has('one'); // true
counters.size; // 1
counters.remove('one'); // true; 다음 get은 새 인스턴스 생성
counters.clear(); // 현재 항목을 해제하고 family는 계속 사용
counters.dispose(); // 영구 종료
```

키는 `Map`과 같은 식별 규칙을 사용합니다. 원시 값은 SameValueZero로 비교하며
`NaN`은 `NaN`과 같고 `0`은 `-0`과 같습니다. 객체는 깊은 동등성이 아니라 참조로
구별합니다. 서로 다른 `{ id: 1 }` 객체는 다른 키입니다. 별도 해시나 직렬화는 없습니다.

항목과 키는 **용량 제한이나 자동 퇴출 없이 강하게 보존**됩니다. 소유 스코프가 끝날 때
`remove`, `clear`, `dispose`를 호출해야 합니다. 구독 해제만으로 family 항목이
퇴출되지 않습니다. `size`와 `has`는 인스턴스를 생성하지 않고 확인할 때 사용합니다.

factory는 항목마다 새로 생성한 독점 소유 인스턴스를 반환해야 합니다. 해제할 때는
캐시에서 먼저 제거하고 인스턴스에 `dispose()`가 있으면 호출한 뒤
`onRemove(instance, key)`를 호출합니다. 구독까지 자동 종료해야 한다면
`withLifecycle`이나 `focus`를 사용합니다. 일반 `Store`에는 dispose가 없으므로
제거는 family의 소유권만 해제하며 외부 참조나 구독은 무효화하지 않습니다.
`onRemove`에서 factory가 소유한 추가 자원을 해제할 수 있습니다.
소유권을 이전할 의도가 없다면 외부에서 공유하는 disposable 인스턴스를 반환하지 마세요.

`onCreate(instance, key)`는 삽입 후 실행되므로 안에서 같은 키로 조회하면 같은
인스턴스를 재사용합니다. callback이 실패하면 해당 항목을 제거하고 해제하며
`onRemove`도 실행합니다. factory 실패는 캐시하지 않습니다. factory가 오류 전에
획득한 자원은 직접 해제해야 합니다. factory에서 같은 키를 재귀적으로 조회하면
중복 생성 대신 오류를 던집니다. callback과 factory는 동기적으로 작성해야 합니다.

`remove`는 없는 항목에 false를 반환합니다. `clear`는 현재 항목의 스냅샷을 만든 뒤
정리 전에 모두 제거하므로 정리 callback에서 새로 만든 항목은 유지합니다.
제거나 해제 중 오류가 나도 나머지 항목과 `onRemove` 정리를 계속하고,
오류는 `AggregateError`로 보고합니다. `dispose`는 정리 전에 영구 종료 상태로
전환하므로 callback에서 새 항목을 만들려 하면 오류를 던집니다. 이후 `get`은
항상 오류를 던지고 `size`는 0, `has`는 false이며 반복 정리는 안전합니다.
family를 해제해도 focus 항목의 부모는 해제하지 않습니다.
