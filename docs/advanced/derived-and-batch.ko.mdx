# 파생 상태, batch와 자원 소유권

이 API는 `@ilokesto/store`에서 제공하며 프레임워크에 의존하지 않습니다.
입력은 `getState`, `getInitialState`, `subscribe`, `subscribeSelector`를 가진
구조적 `ReadableStore<T>`입니다. 구체적인 `Store` 클래스나 프레임워크 런타임이
입력에 필요하지 않습니다.

## 여러 store에서 하나의 값 파생하기

```ts
import { batch, createStore, derived } from '@ilokesto/store';

const price = createStore(10);
const quantity = createStore(2);
const total = derived(
  [price, quantity] as const,
  ([unitPrice, count]) => unitPrice * count,
);
const stop = total.subscribeSelector(
  value => value,
  (next, previous) => console.log({ next, previous }),
);

batch(() => {
  price.set(12);
  quantity.set(3);
});
// 한 번 전달: { next: 36, previous: 20 }.
stop();
total.dispose();
```

`derived(source, compute, options?)`는 단일 입력도 받으며 해당 스냅샷을
`compute`에 직접 전달합니다. 튜플 입력은 readonly 튜플과 인라인 배열을
포함하여 각 입력의 타입을 유지합니다.

생성만으로는 `compute`를 호출하지 않습니다. 최초 읽기 또는 구독에서 현재
결과를 계산합니다. 구독 중에는 입력과 출력을 캐시합니다. 입력이 같은 반복
읽기는 결과를 재사용하며, 구독이 없어도 읽을 때 최신 입력을 확인하므로 연결이
끊긴 동안의 오래된 값을 반환하지 않습니다.

`getInitialState()`는 각 입력의 `getInitialState()`에서 결과를 지연 계산하고
별도로 보관합니다. 최초 구독 시점의 값이라는 뜻이 아닙니다. 입력과 출력은
얕은 readonly 타입이며 복제하거나 런타임에서 동결하지 않습니다. 스냅샷은
불변으로 취급하고 계산은 순수하게 유지하세요. `compute`나 비교 함수에서
입력을 갱신하거나 구독, 자원 해제를 수행하지 마세요.

### Equality와 diamond 그래프

`options.equalityFn(previous, next)`는 출력을 비교하며 기본값은 `Object.is`입니다.
같다고 판단하면 이전 출력 참조를 유지하고 알림을 생략합니다.
`subscribeSelector`는 별도의 선택값 equality와 다음/이전 기준값을 적용합니다.

```ts
const subtotal = derived([price, quantity], ([p, q]) => p * q);
const tax = derived(subtotal, value => value * 0.1);
const invoice = derived([subtotal, tax], ([net, extra]) => net + extra);
```

파생 값의 읽기는 그래프를 따라 현재 입력 스냅샷을 가져옵니다. 알림 계산은
일반 FIFO 전달이 끝난 뒤 처리하므로 같은 입력에서 여러 경로로 이어지는
diamond 그래프도 일관된 최종 결과를 제공하며, 결과가 같으면 중복 알림을
보내지 않습니다. Batch 안에서 읽으면 현재 쓰기를 볼 수 있지만 중간 파생
결과를 알림으로 발행하지는 않습니다.

일반 store selector는 batch 밖에서 기존처럼 기록된 commit을 모두 받습니다.
파생 구독자는 안정된 결과를 관찰합니다. 일반 구독자가 입력을 재진입으로
갱신하면 파생 구독자는 그 중간 입력값을 생략할 수 있습니다. 모든 전이가
필요하면 `Store.subscribeCommit`을 사용하세요.

### 연결과 dispose

첫 파생 구독이 입력에 연결하고 마지막 해제가 연결을 끊습니다. 튜플에서 같은
입력을 여러 번 사용해도 연결은 하나입니다. 재구독하면 현재 입력을 읽고 다시
연결합니다. 같은 리스너를 중복 등록해도 각 구독은 독립적이며 해제는 반복
호출해도 안전합니다.

파생 값은 `ReadableStore<T>`에 `dispose(): void`를 더한
`DisposableReadableStore<T>`를 반환합니다. Dispose는 종료 상태로 전환하며
반복 호출해도 안전합니다. 모든 구독과 입력 연결을 해제하고 대기 중인 계산을
취소하며 보관한 결과 캐시를 비웁니다. 이후 읽기와 구독은 모두 오류를
던집니다. 이미 반환된 해제 함수는 계속 안전합니다. 파생 값을 dispose해도
입력 자체를 dispose하지는 않으며 입력의 수명은 해당 소유자가 관리합니다.

계산이나 출력 비교가 실패하면 이전 전달 기준을 유지합니다. 관련 없는 알림은
계속 처리하며 다음 입력 변경 또는 명시적 읽기로 다시 시도할 수 있습니다.
알림 오류는 현재 대기열을 처리한 뒤 `AggregateError`로 보고합니다.

## 동기 batch

`batch(callback)`은 콜백의 반환값을 반환합니다. 중첩 batch는 가장 바깥 경계를
공유합니다. 변경된 값은 즉시 commit하므로 콜백 안에서도 읽을 수 있습니다.
일반 구독은 store별로 합치며 경계에서 최종 상태로 selector를 평가합니다.
값을 변경했다가 원래 값으로 돌려도 일반 invalidation은 한 번 실행하며,
selector는 equality로 그 전달을 생략할 수 있습니다.

실제 commit마다 구독 목록을 기록합니다. 마지막 쓰기 후 등록한 리스너는
그 이전 store 알림을 받지 않습니다. 해제는 대기 중인 작업에도 즉시
적용됩니다. Batch flush 중 재진입 쓰기는 이미 대기 중인 기록 뒤에 추가되어
먼저 전달되지 않습니다. 기존 알림 처리 중 시작한 batch는 그 전달이 끝난 뒤
처리합니다.

미들웨어는 모든 액션에 실행되고 `subscribeCommit`도 모든 기록을 일반 구독자
이전에 FIFO 순서로 즉시 받습니다. Commit 순번, 교체의 `source` 식별값,
`replaceState`의 미들웨어 우회는 바뀌지 않습니다. Commit 기반 history와
persistence의 의미를 보존합니다. Batch 안에서는 일반 리스너가 `next` 뒤의
미들웨어 코드보다 나중에 실행하며, batch 밖의 기존 동기 순서는 유지됩니다.

Rollback은 제공하지 않습니다. 콜백이 실패해도 저장한 쓰기를 flush합니다.
전달이 성공하면 원래 콜백 오류를 다시 던지고, 전달도 실패하면
`AggregateError`에 콜백 오류를 먼저, 알림 오류를 그 뒤에 담습니다.
모든 활성 대기 알림을 시도하며 이후에도 대기열을 사용할 수 있습니다.
Commit 관측자 오류는 여전히 해당 쓰기 호출에서 발생합니다.

동기 콜백만 지원합니다. TypeScript는 Promise를 반환하는 콜백을 거절합니다.
JavaScript에서는 `async`를 사용하지 마세요. Batch는 Promise 완료 시점이
아니라 콜백이 반환하는 시점에 끝납니다.

## 크기가 제한된 메모이제이션

`memoizeSelector(selector, { maxSize?, equalityFn? })`는 호출 가능한 selector와
`size: number`, `clear(): void`를 제공합니다. 각 인스턴스는 독립적인 LRU
캐시를 소유합니다. `maxSize` 기본값은 `1`이며 양의 안전한 정수여야 합니다.
전역 캐시는 없습니다. `equalityFn`은 입력을 비교하며 기본값은 `Object.is`입니다.
실패한 계산은 캐시하지 않습니다.

```ts
import { memoizeSelector } from '@ilokesto/store';

const selectTotal = memoizeSelector(
  (items: readonly number[]) => items.reduce((sum, item) => sum + item, 0),
  { maxSize: 4 },
);
const items = [10, 20];
selectTotal(items); // 30
selectTotal(items); // 캐시 결과 재사용.
selectTotal.clear();
```

`derived`도 크기가 제한된 입력 튜플 캐시를 사용합니다. `options.cacheSize`로
기본 제한 `1`을 변경할 수 있습니다. 튜플 요소는 `Object.is`로 비교하며 출력
equality와는 별개입니다. 구독이 없어도 이 제한 안에서 입력 튜플과 출력
참조를 보관하고 `dispose`에서 해제합니다. 입력과 결과 참조를 유지하므로
작은 제한을 선택하세요.

## 첫 구독에서 시작하고 마지막 해제에서 정리하기

`withLifecycle(source, start)`는 구조적 입력을 감싼
`DisposableReadableStore<T>`를 반환합니다. 읽기만으로 자원을 시작하지
않습니다. 첫 일반 구독 또는 selector 구독이 `start(scope)`를 동기 실행하며
마지막 구독 해제에서 정리합니다. 추가 구독과 중복 등록은 같은 활성 자원을
공유합니다.

```ts
import { createStore, withLifecycle } from '@ilokesto/store';

const width = createStore(window.innerWidth);
const liveWidth = withLifecycle(width, ({ onCleanup }) => {
  const update = () => width.set(window.innerWidth);
  window.addEventListener('resize', update);
  onCleanup(() => window.removeEventListener('resize', update));
  update();
});

const stop = liveWidth.subscribe(() => console.log(liveWidth.getState()));
stop();
liveWidth.dispose();
```

`start`는 정리 함수를 반환할 수 있습니다. `scope.onCleanup(cleanup)`은 자원을
얻는 즉시 정리 함수를 등록하므로 이후 시작 코드가 실패해도 앞서 얻은
자원을 해제합니다. 정리는 등록의 역순으로 한 번씩 실행하며 반환한 정리
함수는 마지막에 등록됩니다. 자원을 얻으면 즉시 정리 함수를 등록하세요.
등록하지 않고 방치한 자원은 래퍼가 회수할 수 없습니다.

구독자는 시작 전에 등록되므로 시작 중 동기 쓰기의 알림도 받을 수 있습니다.
재진입 구독은 같은 자원을 두 번 시작하지 않습니다. 시작이 실패하면 해당
활성화의 구독을 취소하고 등록한 정리를 수행하며 이후 다시 구독할 수
있습니다. 정리 함수가 재구독하면 이전 정리가 모두 끝난 후 다음 자원을
시작합니다. 정리 오류가 있어도 나머지 정리를 수행하고, 오류 하나는 그대로
다시 던지며 여러 오류는 `AggregateError`로 모읍니다.

`dispose()`는 래퍼의 모든 구독을 취소하고 정리가 실패해도 종료 상태를
유지합니다. 입력 자체는 dispose하지 않습니다. 시작 중 dispose하면 시작
콜백이 나중에 반환한 정리 함수도 실행합니다. 구독 시작과 정리는 동기여야
하며 비동기 자원의 소유권은 상위 어댑터에서 관리합니다.
