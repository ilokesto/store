# 선택적으로 사용하는 속성 추적 파생 상태

`trackedDerived(source, compute, { equalityFn? })`는 `@ilokesto/store`에서
선택적으로 사용하는 export입니다. [derived](./derived-and-batch)와 같은
구조적 readable인 `DisposableReadableStore<Selection>`을 반환합니다.
기존 selector, equality 기본값과 프레임워크 binding은 바뀌지 않습니다.

```ts
import { createStore, trackedDerived } from '@ilokesto/store';

const source = createStore({ count: 1, theme: 'light' });
const doubled = trackedDerived(source, state => state.count * 2);
const stop = doubled.subscribeSelector(
  value => value,
  (next, previous) => console.log({ next, previous }),
);

source.update(state => ({ ...state, theme: 'dark' })); // 계산 생략.
source.update(state => ({ ...state, count: 2 })); // 계산 후 4, 2 전달.
stop();
doubled.dispose();
```

입력은 구조적 `ReadableStore<State>`이면 됩니다. 결과는 `getState`,
`getInitialState`, `subscribe`, `subscribeSelector` 계약을 받는 모든 readonly
binding에서 사용할 수 있습니다. 쓰기 메서드나 프레임워크 런타임은 필요하지
않습니다. 여러 입력을 합칠 때는 `derived`와 조합하세요.

생성은 지연 방식이며 연결이 끊긴 동안에도 읽을 때 최신 입력을 확인합니다.
첫 구독이 입력에 연결하고 마지막 해제가 연결을 끊으며 재구독은 값을
갱신합니다. Batch, 안정된 그래프 알림, 초기 스냅샷, 오류 전파와 종료 상태의
`dispose()`는 `derived`를 따릅니다. 인스턴스마다 추적 의존성/결과 기록을
하나 보관하며 LRU 이력은 아닙니다. Dispose하면 해제합니다.
`getInitialState()`는 입력의 초기 스냅샷에서 계산한 출력을 별도로 보관합니다.

`equalityFn`은 출력을 비교하며 기본값은 `Object.is`입니다. 같으면 이전 출력
참조를 유지하고 알림을 생략합니다. 성공한 계산은 출력이 같아도 추적 의존성을
교체합니다. 실패한 계산의 부분 의존성은 발행하지 않습니다.

## 정확한 추적 경계

이 API는 **얕은 속성 추적**이며 deep proxy 추적이 아닙니다. 동기 계산 중에
일반 plain object, null-prototype 객체와 일반 배열을 임시 루트 proxy로
전달합니다. 동결한 스냅샷도 지원합니다. 새 루트 스냅샷에서 관찰한 의존성이
모두 같을 때만 결과를 재사용합니다.

| 관찰 | 의존성 |
| --- | --- |
| `state.count`, `state[key]` | 반환값을 `Object.is`로 비교하며 문자열과 symbol 키 지원 |
| 없거나 optional인 속성 | 읽은 값; 값 읽기에서는 부재와 명시적인 `undefined`가 같음 |
| `'key' in state` | 상속 속성을 포함한 존재 여부 |
| `Object.hasOwn(state, 'key')` | 부재를 포함한 own property descriptor |
| `Reflect.ownKeys(state)` | symbol과 열거 불가 속성을 포함한 모든 own key와 순서 |
| `Object.keys`, 객체 spread, `for...in` | 해당 연산이 확인한 키와 descriptor/값 |
| `Object.getOwnPropertyDescriptor` | 값, getter/setter 참조와 플래그를 포함한 전체 descriptor |
| 배열 인덱스, 길이, 순회, `map` | 읽은 루트 인덱스, 길이, 존재 여부와 메서드 |
| Prototype 또는 extensibility 검사 | Prototype 참조는 항상 비교하고 extensibility는 관찰했을 때 비교 |

Descriptor 추적은 보수적입니다. `Object.keys`와 `Object.hasOwn`은 결과 키
목록이나 boolean이 같아도 descriptor의 값이 바뀌면 다시 계산할 수 있습니다.
출력 equality는 여전히 알림을 생략할 수 있습니다. Accessor의 receiver는
원본 스냅샷입니다. 관찰한 값을 확인하기 위해 `compute`를 생략해도 getter를
호출할 수 있으므로 getter도 순수해야 합니다.

매번 성공한 계산에서 의존성을 다시 구성합니다.
`state.useLeft ? state.left : state.right`는 비활성 분기를 읽지 않습니다.
분기를 바꾸면 새 값의 추적을 시작하고 이전 값의 추적을 멈춥니다.

중첩 객체와 배열은 **원본 참조를 비교하는 의존성**입니다.

```ts
const name = trackedDerived(sourceWithUser, state => state.user.name);
```

여기서는 중첩된 `name` 경로가 아니라 `user`를 추적합니다. 다른 루트 필드를
교체해도 `user` 참조를 유지하면 계산을 생략합니다. `user`를 교체하면
`user.age`만 달라져도 다시 계산합니다. `state.user`를 반환하면 원본 참조를
유지합니다.

루트가 `Date`, `Map`, `Set`, class 인스턴스, 함수 또는 사용자 정의 prototype
객체이면 속성을 추적하지 않습니다. 원본을 `compute`에 전달하고 루트 참조가
바뀔 때마다 계산합니다. 중첩된 인스턴스도 원본 그대로 전달하며 참조로
비교합니다. 따라서 네이티브 메서드와 private field의 receiver가 유효하고,
서로 다른 날짜나 Map에 열거 가능한 속성이 없다는 이유로 같다고 판단하지
않습니다. 원시 값과 nullish 스냅샷은 일반 참조/값 메모이제이션을 사용합니다.

모든 스냅샷, 중첩 값과 prototype은 불변이어야 합니다. `Map`이나 `Date`를
바꿀 때도 새 인스턴스로 교체하세요. 제자리 변경은 지원하지 않습니다.
이 API는 변경 감시, 동결이나 재귀 readonly 타입을 추가하지 않습니다.
사용자가 전달한 proxy와 외부에서 변경하는 prototype은 추적 계약 밖입니다.

계산은 순수하고 동기여야 합니다. 추적 proxy를 통한 루트 쓰기는 오류를
던지며 중첩 원본 값도 변경하면 안 됩니다. 임시 루트를 참조로 비교하거나
`Map`/`WeakMap` 키로 사용하거나 보관하지 마세요. 반환 함수에서 캡처하거나
반환 객체 안에 넣어서도 안 됩니다. 계산이 끝나면 proxy를 revoke하므로
탈출한 읽기는 의존성을 몰래 바꾸는 대신 실패합니다. 루트를 직접 반환하는
`state => state`는 지원하며 원본 스냅샷을 반환하고 전체 루트 참조로
무효화합니다. 제약 없는 루트 참조 연산이나 비동기 작업에는 일반 `derived`와
명시적인 입력을 사용하세요.

## 계산 횟수와 렌더 무효화 비교

아래 예제는 경과 시간이 아닌 계산 횟수를 관찰합니다. 카운터는 진단용이며
실제 계산 함수는 순수하게 유지하세요.

```ts
import { createStore, derived, memoizeSelector, trackedDerived } from '@ilokesto/store';

const source = createStore({ count: 1, other: 0 });
let trackedCalculations = 0;
let memoCalculations = 0;
let trackedInvalidations = 0;
let memoInvalidations = 0;

const tracked = trackedDerived(source, state => {
  trackedCalculations++;
  return state.count * 2;
});
const memoized = derived(source, memoizeSelector(state => {
  memoCalculations++;
  return state.count * 2;
}));
const stopTracked = tracked.subscribe(() => { trackedInvalidations++; });
const stopMemo = memoized.subscribe(() => { memoInvalidations++; });

for (let other = 1; other <= 100; other++) {
  source.set({ count: 1, other });
}
source.set({ count: 2, other: 100 });
// 최초 계산 포함: tracked 2회, memoized 102회.
// 무효화 알림: tracked 1회, memoized 1회.

stopTracked();
stopMemo();
tracked.dispose();
memoized.dispose();
```

원시 값 출력은 둘 다 한 번만 알리므로 계산이 줄었다고 렌더도 반드시 줄지는
않습니다. 두 계산이 기본 equality로 새 객체
`{ doubled: state.count * 2 }`를 반환하면 tracked 출력은 한 번, 루트 참조
메모이제이션은 101번 무효화합니다. Readonly UI binding은 이 알림으로 렌더를
요청할 수 있지만 실제 컴포넌트 렌더 횟수는 프레임워크 batch, 개발 모드 검사와
부모 렌더에도 달려 있습니다. 아래 수치는 테스트한 알림 횟수이며 프레임워크의
실제 렌더 횟수를 측정한 것은 아닙니다.

| 무관한 쓰기 100회와 count 변경 1회 후 출력 | Tracked 계산 | 루트 참조 메모이제이션 계산 | Tracked 알림 | 메모이제이션 알림 |
| --- | --- | --- | --- | --- |
| 숫자 | 2 | 102 | 1 | 1 |
| 새 객체, 기본 equality | 2 | 102 | 1 | 101 |

결정적인 비교 테스트는 `src/trackedDerived.test.ts`에 있습니다. 실행 시간의
우위를 주장하지는 않습니다. 추적에는 proxy와 의존성 비교 비용이 들고
열거는 모든 키를 검사할 수 있습니다. 저렴한 selector나 관찰한 필드가 자주
바뀌는 경우에는 이득이 없을 수 있습니다. 안정된 입력을 먼저 명시적으로
선택하여 `memoizeSelector`에 전달하거나 `derived`에 적절한 출력 equality를
주면 추적 없이 같은 계산 또는 알림을 줄일 수 있습니다. 의존성이 단순하면
그 방식을 우선하고, 분기별 루트 읽기에 수동 입력 비교를 반복해야 하는
경우에 이 선택적 API를 사용하세요.
